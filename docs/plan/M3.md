# M3 — Static timing analysis (`dla/sta`)

Goal: graph-based STA on the gate-level `Design` with NLDM delays from Liberty and
an SDC subset, `report_timing`-style path reports, setup and hold. Completion:
same netlist + SDC as OpenSTA gives WNS / TNS and the top path delays within ±2 %.

## Scope

| In M3 | Later |
|---|---|
| Timing graph: one vertex per pin (instance pins, ports), cell arcs from Liberty, net arcs driver → loads | false / multicycle paths, generated clocks |
| NLDM delay calculation, rise / fall separately, slew propagation (worst slew per vertex and transition) | CCS, effective capacitance (M7 with SPEF) |
| Net load: sum of input pin caps (+ `set_load` on ports); net delay 0 (lumped C) | wire RC from SPEF: Elmore, then Ceff (M7) |
| Max (setup) and min (hold) analysis; unateness (positive / negative / non-unate) | clock reconvergence pessimism removal |
| Ideal clocks (`create_clock` period / waveform); latency 0 at FF clock pins, `set_clock_transition`, `set_clock_uncertainty` | propagated clocks through the CTS tree (M5) |
| Sequential arcs: clock → Q (`rising_edge` / `falling_edge`), checks setup / hold, recovery / removal; async clear / preset arcs | latches (time borrowing) |
| State-dependent (`when`) arcs: worst over all arcs of the same pin pair | mode-specific `when` selection |
| SDC: `create_clock`, `set_input_delay`, `set_output_delay`, `set_load`, `set_driving_cell`, `set_input_transition`, `set_clock_uncertainty`, `set_clock_transition`; `[get_ports …]`, `[get_clocks …]`, `[all_inputs]`, `[all_outputs]`, globs, `{…}` lists, `-max` / `-min`, `-rise` / `-fall` | full Tcl |
| Reports: per-path table (pin, cell, transition, incr, path, slew, load), slack MET / VIOLATED, WNS / TNS / violating endpoints for setup and hold | SDF writing (M8, optional) |

## Data structures (`dla/sta`)

```
Graph(design, liberty)
  vertices: (inst, pin) | ("PIN", port) -> id; per vertex: is_clock, is_ff_d, is_po, ...
  edges:    cell arcs (from, to, TimingArc, kind comb|clk2q|clear|preset)
            net arcs (driver vertex -> load vertex)
  checks:   (data vertex, clock vertex, TimingArc setup/hold/recovery/removal)
Sdc: clocks {name: Clock(period, waveform, ports, uncertainty, transition)},
     input_delay / output_delay [(port, clock, edge, max/min, rise/fall, value)],
     loads {port: pF}, driving {port: (cell, pin) | slew}
Timer(graph, sdc)
  arrival[v][rf][max|min], slew[v][rf][max|min], required, slack
  update(): levelise (cell + net arcs, FF D->Q cut), forward pass, backward pass
  report_timing(n=5, kind="setup"|"hold") -> text; summary() -> WNS, TNS, #viol
```

Units: ns, pF everywhere (Liberty values are already converted by `dla.db.liberty`).

## Algorithms

- Levelisation by Kahn's algorithm on cell + net arcs; FF clock→Q arcs start paths,
  D pins end them; combinational loops are reported and stop analysis.
- Delay calculation per cell arc and transition: load = Σ fanout pin caps (rise / fall
  cap when given) + port load; delay and output slew from `cell_rise/fall`,
  `rise/fall_transition` at (input slew, load); output transition follows
  `timing_sense`. Slew taken from the arc that sets the worst arrival (as OpenSTA's
  default "worst slew" mode does per vertex); differences show up in the oracle
  comparison and are documented.
- Input ports: arrival = input delay; slew from `set_input_transition`, or from the
  driving cell's arc at the port load; outputs: required = period − output delay.
- Checks: setup required = capture edge + period … − setup(constrained slew, related
  slew) − uncertainty; hold required = launch edge + hold + uncertainty.
- Paths: back-tracing the arc that produced each worst arrival.

## CLI

```bash
python gen.py --tech T sta --netlist out/TOP/synth.v --sdc bench/TOP.sdc [--corner typ]
# [sta ] setup WNS ..., TNS ..., violations ...; hold WNS ...  -> out/TOP/reports/sta.rpt
```
Every bench gets an `.sdc` (clock period chosen near its critical delay so that both
passing and failing endpoints exist).

## Tests

1. Hand-computed cases on `tests/data/tiny.lib`: chain of NAND2/INV with scalar and 2-D
   tables (interpolation, unate / non-unate, rise / fall), FF → logic → FF setup / hold,
   input / output delays, `set_load`, uncertainty — exact numbers.
2. SDC parser: every command form above, errors with line numbers.
3. Oracle (`tests/oracle/test_sta_opensta.py`): every bench netlist + SDC, OpenSTA vs
   ours: WNS, TNS and the worst path delay of the top 10 endpoints within ±2 % (setup
   and hold). Skips when `sta` is not installed.

## Risks / open items

- **OpenSTA is not available in this container.** Building it from source needs the
  CUDD BDD library, which is not packaged here and whose download from an external
  source was refused by this session's permission policy. Without the oracle, M3's
  completion criterion (±2 % vs OpenSTA) cannot be checked here; the hand-computed tests
  still run. See the options reported to the user.
- Slew merging and `when`-arc selection differ between tools; differences beyond 2 %
  will be investigated against OpenSTA's reports, not tuned blindly.
