# M0 — Survey and foundation (`dla/db`)

Goal: a netlist-based design database that every later stage (synth, STA, place,
CTS, route, signoff) reads and writes, plus file I/O for LEF, DEF and structural
Verilog. The existing generator flow (`Block`, `Tech`, decoder, std-cell generator)
stays untouched.

## Scope

| In M0 | Deferred |
|---|---|
| `docs/ARCHITECTURE.md` (modules, data flow, units, coordinates) | Liberty (M1), SDC (M3), SPEF (M7) |
| `dla/db`: `Library`, `Design` and their parts | `Block -> Design` converter (M4, when macros enter the flow) |
| LEF read (tech + cells: units, layers, vias, via rules, sites, macros) | LEF write (only generated cells need it; `dla/stdcell/writers.py` has one) |
| DEF read / write (sections below) | DEF `REGIONS`, `GROUPS`, `NONDEFAULTRULES`, `FILLS`, `SCANCHAINS`: clear error |
| Structural Verilog read / write (flat netlists) | Hierarchical netlists (flattening comes with `dla/rtl` in M2) |
| tech file: optional `files.tech_lef` | the full `layers.routing` stack (M6) |

## Data structures (`dla/db`)

Units: **µm floats rounded to 6 decimals** (`r6`) everywhere in memory, as in the
existing code. DEF integer database units are converted on read/write only
(`round(v * dbu)`), so a read→write→read round trip is exact as long as values sit
on the DBU grid (they always do when they came from a DEF).

```
Library                       # from one or more LEF files
  dbu, mfg_grid
  layers   {name: LayerDef}   # type ROUTING/CUT/MASTERSLICE/..., direction, pitch, offset,
                              # width, spacing (+ table), area, rpersq, cpersqdist, edgecap
  layer_order [name]          # LEF order = bottom-up stack
  vias     {name: ViaDef}     # fixed vias: [(layer, rect)], default flag, resistance
  viarules {name: ViaRuleDef} # GENERATE rules (layer enclosures, cut rect, spacing)
  sites    {name: Site}       # class, symmetry, w, h
  macros   {name: Macro}      # class, origin, foreign, w, h, symmetry, site,
                              # pins {name: MacroPin(direction, use, shape, ports=[(layer, rect|poly)])},
                              # obs [(layer, rect|poly)], pin_order [name]

Design
  name, dbu, die (x1, y1, x2, y2)
  insts    {name: Inst}       # master, x, y, orient (N S E W FN FS FE FW), status
                              # (UNPLACED PLACED FIXED COVER), source
  ports    {name: Port}       # bit-level name ("a[3]"), direction, use, net,
                              # shapes [(layer, rect)], status, x, y, orient
  nets     {name: Net}        # use, conns [(inst | "PIN", pin)], wiring [Path]
  specialnets {name: Net}     # same, with path widths and shapes
  rows     [Row]              # name, site, x, y, orient, nx, ny, sx, sy
  tracks   [Tracks]           # axis X|Y, start, num, step, layers
  gcells   [GCellGrid]
  vias     {name: DefVia}     # DEF VIAS: rect list or via-rule parameters
  blockages [Blockage]        # placement / layer, rects
  buses    {base: (msb, lsb)} # Verilog bus declarations kept for writing
```

`Path` keeps a DEF routing statement exactly enough to round-trip and to turn into
geometry later: `layer, width (special nets), shape, mask-free elements` where each
element is a point `(x, y, ext)`, a via name, or a `RECT`/`VIRTUAL` element; `*`
coordinates are resolved on read.

Orientation helpers (`dla/db/geom.py`): transform a macro-local rect to design
coordinates for any of the 8 DEF orientations (placement point = lower-left of the
transformed bounding box, the DEF convention). The existing `Block` row
orientations map `R0 -> N`, `MX -> FS`.

## Algorithms / parsing

- One tokenizer per format (whitespace + `;`, `(`, `)` as separate tokens; DEF and
  LEF strings in quotes; `#` comments). Parsers are hand-written recursive descent,
  every error carries file name and line number.
- Unknown LEF statements inside a known block are skipped up to `;` (LEF has many
  rule statements the flow does not need yet); unknown LEF *blocks* are skipped to
  their `END`. Unknown DEF sections raise an error (silently dropping placement or
  routing would be worse than stopping).
- Verilog: tokenizer handles comments, escaped identifiers, sized constants;
  parser accepts `module`, ANSI and non-ANSI port lists, `input/output/inout/wire`
  with ranges, `assign lhs = rhs` (bit or bus aliases and constants), cell instances
  with named (`.A(n)`) or positional connections, bit-selects, part-selects and
  concatenations. Anything else stops with `file:line: unsupported ...`.
  Buses are bit-blasted into `name[i]` nets. `assign` aliases are merged with
  union-find; a port name wins as the net name. Constant connections become the
  pseudo-nets `1'b0` / `1'b1` (written back as literals; DEF write refuses them:
  tie cells are inserted by synthesis).
- Writers emit a canonical order (insertion order of dicts = file order), so the
  output is deterministic and diff-friendly.

## Tests (`tests/test_db.py`)

Without PDK (always run):
1. Tiny hand-written LEF (`tests/data/tiny.lef`) parses: layers, vias, sites, macros, pins.
2. Hand-written DEF (`tests/data/small.def`, rows, tracks, components placed/fixed/
   unplaced with all orientations, pins, special nets, routed nets with vias, `*`,
   extensions, RECT, blockages, DEF vias): read→write→read gives an identical
   `Design` (compared via a canonical dict) and write is idempotent (byte-equal).
3. Structural Verilog: buses, part-selects, concatenation, assign aliases,
   constants, escaped names; read→write→read identical; malformed input yields an
   error with a line number.
4. Orientation transform: all 8 orientations against hand-computed boxes.

With `DLA_TECH` (IHP):
5. IHP tech + std-cell LEF: 84 macros, metal stack Metal1..TopMetal2 in order with
   directions/pitches, `Via1_XX` geometry, CoreSite 0.48 x 3.78; every macro's size
   matches `dla.tech.parse_lef`.
6. A small DEF built on IHP cells round-trips; KLayout's own LEF/DEF reader reads
   our written DEF with the IHP LEFs and sees the same instances (independent check
   of DEF syntax).

## Risks

- DEF/LEF are large formats; the subset is chosen to cover what OpenROAD writes for
  a simple flat design. Anything outside it fails loudly, so gaps show up as clear
  errors when the oracle tests start in M4/M6.
- µm floats: all coordinates pass through `r6`; conversion to DBU uses `round`, so
  values off the DBU grid would be snapped silently — the DEF writer checks this and
  raises instead.
- The repository `.gitignore` ignores `*.lef`; the hand-written test LEF is added
  through an explicit exception (`!tests/data/*.lef`), it contains no PDK data.

Open points carried forward:
- No oracle in this container (OpenROAD/Yosys not installed); DEF syntax was
  cross-checked with KLayout's reader only. DEF written by OpenROAD may use sections
  outside the subset (e.g. `NONDEFAULTRULES`, `REGIONS`); they fail loudly and get
  added when the M4/M6 oracle tests meet them.
- Bus pins on cells (`.D(bus[3:0])` to a macro with `D[3]`..`D[0]`) are rejected;
  needed once hard macros enter the flow.
- `Block → Design` conversion moves to M4 (floorplan with macros).
